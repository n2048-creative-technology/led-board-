# Documentation generators

Everything in [`images/`](../images) is generated by these scripts. Nothing here
needs hardware attached.

| Script | Output | What it does |
|---|---|---|
| `mkshots.py` | `images/webui/*.png` | Screenshots of the ESP32-served web UI |
| `mkdiagrams.py` | `images/diagrams/*.svg` | The four README diagrams |
| `export-kicad.sh` | `images/schematic/*` | Schematic SVG + PDF, PCB layer SVGs, 3D render |
| `rasterize.sh` | `*.png` beside each SVG | Preview render of an SVG, via Chrome |

```bash
python3 scripts-tools/mkshots.py
python3 scripts-tools/mkdiagrams.py
bash    scripts-tools/export-kicad.sh
```

Requires `google-chrome` on `PATH`, Pillow for `mkshots.py`, and KiCad for
`export-kicad.sh` — it finds either `kicad-cli` or the snap's
`kicad.kicad-cli`. The snap is confined to `$HOME`, which is why the export
script always writes inside the repo.

## How the screenshots stay honest

`mkshots.py` does not keep a copy of the page. It extracts the
`R"HTML(...)HTML"` literal out of `firmware/src/main.cpp` at run time, then
injects a shim that replaces `window.fetch` with a reimplementation of the
firmware's `/api/*` handlers — including the integer power maths
(`estimateMilliamps` / `computeHoldLevel`), so the hold level and mA readouts on
screen are the numbers the board would actually report. Change the UI in the
firmware, re-run, and the README is current.

The variants captured (default yellow, lights off, another colour at a 15 A
budget, phone width) are the `shoot(...)` calls at the bottom of the file. Card
crops come from bounding boxes measured in the live page, not fixed pixel
offsets, so they survive layout changes.

## How the diagrams stay honest

`mkdiagrams.py` writes SVG directly. The animation diagram is not drawn by hand:
`strip_levels()` and `breathe_wave()` are line-by-line ports of `renderFrontAt()`
and `breatheWave()` from `main.cpp`, gamma table included, so the LED gradients
and the breathing curve are the firmware's real output.

## Do not use ImageMagick on these SVGs

`convert` falls back to ImageMagick's internal SVG renderer here, which silently
drops `fill-opacity` (every LED renders fully lit) and mis-measures text.
`rasterize.sh` goes through Chrome instead:

```bash
scripts-tools/rasterize.sh images/diagrams/animation.svg
```
